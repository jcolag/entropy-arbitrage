## Mini-Server, Part 27

I don't know that anybody would care about this sort of detail but me, but for those who do, I managed a *tiny* step forward on that rogue server that collapses under load.  The company apparently can't trouble itself to produce documentation, but they do inexplicably record shoddy videos on disassembly.  Once I landed on searching for removing the fan---not what I want to do, and I have no idea what would make that anybody's target---I found a fairly thorough tear-down.

I overlooked "grip the ports on one side of the motherboard and give it a yank" as a way to get at the protected side with the CPU and fan, because, you know...that *feels obscenely reckless*.  This gives me enough access that I can investigate how the fan behaves as the processor heats up and check any heat sinks.

I also tried to build the [OpenSCAD Web GUI](https://seasick.github.io/openscad-web-gui/) to drop on a server, but the interface itself requires already having the [non-interface parts built for the browser](https://github.com/openscad/openscad-wasm), and the latter somehow uses [Docker](https://www.docker.com/) to run the compiler, which...I have no interest in installing Docker to see if it'll work or why they can't run the same compilers that everybody else uses.

It doesn't need to *run* in a Docker container, understand.  No, it needs Docker to run the thing that makes the scripts that get dropped on a server to run arbitrarily.

## Entropy Arbitrage

{% codeberg jcolag/entropy-arbitrage-code %}

First, I should note that Mozilla made their big decision during the week and decided to [extend Firefox 115 ESR support](https://whattrainisitnow.com/release/?version=esr) yet again, now to March 2027.  That continues my postponement of the [Popover experiments](/blog/popover), because running the [relevant version](https://ftp.mozilla.org/pub/firefox/releases/115.0esr/) for Linux[^Tnm4fQ], Popovers absolutely do *not* degrade gracefully.  It leaves the buttons in place doing nothing, but treats the boxes themselves as ordinary `div` elements, inline to the text.

[^Tnm4fQ]:  I needed to run `./firefox --no-remote --new-instance` to get it running without trying to glom onto my existing Firefox profile, in case somebody needs to do some similar testing.

This also (pretty much by definition) scuttles the half-idea of using the boxes and the even newer [anchor positioning API](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Anchor_positioning) to create nicer looking title-text when hovering over at least some items.

It looks like OKLCH colors also don't work in the older ESR at all, but I don't mind asking the couple of readers still sticking with Windows 7--8.1 or macOS 10.12--10.14 to deal with a gray color scheme that actually doesn't look all that bad.

Otherwise, a lot of the work this week went to fielding feedback on the now-persistent header bar.  Apparently, making an object `sticky` does not, in fact, do anything more than simplify positioning, leaving the rest of the page to scroll incorrectly.  As such, I reordered the page layout so that the header stands outside the article space (probably what it should've always done), and adjusted the scroll offsets.

In addition, the [about page](/blog/about) should also make a bit more sense, as well as the still-hidden feature.

You'll also see a quick prototype for a plugin for Wikipedia links.  Unless I missed something, the push to [unionize the Wikimedia Foundation](https://wikiworkersunited.org/), so I wanted to have it ready in the event that they call for a boycott.  By replacing the existing links with the plugin (not done), I can track down a relatively up-to-date mirror and change all the URLs in one build by changing the structure in the plugin.

Relevant to the Popover drama above, I threw together a JavaScript function to flag browsers that don't have the capability.  If I decide to move forward despite the single browser still not supporting the feature, I'll want some fallback for anything there.
